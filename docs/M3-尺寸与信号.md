## 模块 1（3.1）终端尺寸查询

**产出**：`Terminal::Size` 与 `Terminal::size()` 可用；HUD/日志能显示当前行列数。

**学习内容**

- `man 2 ioctl`：`TIOCGWINSZ`、`struct winsize` 的 `ws_row / ws_col`
- 为什么不能依赖 `LINES` / `COLUMNS` 环境变量（程序运行中不会更新）
- tty 与 pipe 的区别：重定向/管道时 `ioctl` 会失败，需要回退值

**提示（少量）**

1. `#include <sys/ioctl.h>`；`winsize ws{}`；`::ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws)`。
2. 返回 0 才成功；失败或 `ws_row/ws_col == 0` 时回退到默认值（如 24×80）。
3. 尺寸是“字符格”，不是像素；`ws_xpixel/ws_ypixel` 这关不需要。
4. 自测：把 `WxH` 画到 HUD 或临时打到 `stderr`，和终端里的 `stty size` 对照。

**验收**

- [ ] 真终端里 HUD 的尺寸和 `stty size` 输出（行 列）一致
- [ ] `printf 'q' | ./build/snake_client` 走回退值，不崩
- [ ] 全程 0 warning

**常见坑**：ioctl 的 fd 用错；不判断返回值；把 0×0 当合法尺寸；把像素宽当列数。

## 模块 2（3.2）SIGWINCH：让缩放事件到达主循环

**产出**：终端一缩放，主循环能立刻感知；不缩放时零开销。

**学习内容**

- `SIGWINCH` 的默认动作是**忽略**：不安装处理器就完全收不到通知
- `sigaction` / `sa_flags`；`poll` 被信号打断后返回 `-1/EINTR`
- 异步信号安全：handler 里只能做极少的事（置 `volatile sig_atomic_t`）

**提示（少量）**

1. 加一个 `volatile sig_atomic_t winch_pending = 0;`，handler 里只写 `winch_pending = 1;`。
2. 用 `sigaction` 安装 `SIGWINCH`，`sa_flags = 0`（和 SIGINT/SIGTERM 一致）。
3. M2 已经把 `poll` 的 `EINTR` 映射成 `TIME_OUT`，所以缩放会立刻把 `read_char` 唤醒；主循环在下一轮检查标志即可。
4. 自测：在主循环里（不是 handler 里）发现标志时往 `stderr` 打一行，拖动窗口确认能收到。

**验收**

- [ ] 拖动/缩放终端，调试计数增加；不缩放时计数不变
- [ ] 缩放不会让游戏退出；`q` 仍然有效
- [ ] 0 warning

**常见坑**：不装 handler 以为会收到信号；在 handler 里 `printf`/`ioctl`/`malloc`；标志类型不是 `sig_atomic_t`；忘记在循环里清零标志（会每帧都触发清屏）。

## 模块 3（3.3）缩放后的重排与重画

**产出**：缩放终端不乱画；窗口太小时显示提示而不是花屏。

**学习内容**

- 终端自动换行：一行写的字符数超过窗口宽度时会折行，整屏布局错位
- 「一次性清屏」与「每帧清屏」的区别：前者用于 resize，后者会闪
- 布局检查与游戏状态分离：缩放只是重排，不是重开

**策略选择（M3 推荐 A）**

- **A. 固定棋盘 + 太小提示**：棋盘尺寸不变；放不下就清屏显示提示，等窗口变大再恢复。
- B. 响应式棋盘：棋盘跟随窗口伸缩，蛇/食物坐标也要跟着缩放——留给 M7。

**提示（少量）**

1. 最小尺寸按真实布局算：外围宽 = `kBoardCols + 2`；行数 = 顶部边框 1 + 内部 `kBoardRows` + 底部边框 1 + HUD 1 = `kBoardRows + 3`。
2. 处理顺序：`winch_pending` 置位 → 清零 → `term.clean()`（清屏一次）→ 重新 `size()` → 更新 `too_small`。
3. `too_small` 时只画提示文字（固定宽度、末尾补空格），不画棋盘和 HUD；窗口恢复后下一帧自然重画。
4. 每帧仍然全量重画；`\033[2J` 只在 resize/启动时用一次。
5. 缩放不修改游戏状态（`@` 位置、方向都保留）。

**验收**

- [ ] 启动时窗口就小于最小尺寸：显示提示，无花屏
- [ ] 运行中「大 → 小 → 大」来回缩放：每次都能正确恢复，无残影
- [ ] 贴着右/下边界时缩放：不崩、不越界
- [ ] `q` / `Ctrl+C` / `< /dev/null` 三条路径正常
- [ ] CPU 低；0 warning

**常见坑**：写超窗口宽度导致自动换行；resize 后不清屏导致重排残影；每帧清屏导致闪烁；标志不清零；尺寸为 0 未处理。

## 五、速查表

| 事项 | 用法 |
|---|---|
| 查询终端尺寸 | `ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws)` |
| 当前终端尺寸 | `stty size`（输出 `行 列`） |
| 缩放信号 | `SIGWINCH`（默认忽略，必须装 handler） |
| 信号打断等待 | `poll` 返回 `-1`，`errno == EINTR`（M2 已映射为 `TIME_OUT`） |
| 清屏（仅 resize 时） | `\033[2J\033[H`，即 `Terminal::clean()` |
| 花屏救援 | `reset` / `stty sane` |
