## 模块 1（2.1）poll 超时读键

**产出**：`read_char(int timeout_ms)` 可用；主循环以它空转不占 CPU。

**学习内容**

- `man 2 poll`：`struct pollfd` 的 `fd / events / revents`；返回值 `>0` / `0` / `-1` 三个含义；超时参数 `-1` / `0` / `>0`（毫秒）三种取值；`EINTR` 是怎么来的
- `man 2 read`：返回 `1` / `0` / `-1` 分别代表什么；`errno` 的意义
- 复习 M1 的知识点：`ISIG` 保留 + `sa_flags = 0`，所以 `Ctrl+C` 会打断 `poll`

**提示（少量）**

1. `poll` 只负责「等」，真正取字节还是 `read`；两步都在函数内完成。
2. 返回值建议用小枚举 `Char / Timeout / Eof` 三态，`std::optional<char>` 分不清超时和 EOF——M5 网络层会复用同样的三态思想。
3. `poll` 返回 `-1`（含 `EINTR`）时**不重试也不退出**，按「无输入」处理，让主循环条件决定生死。
4. `revents` 里确认 `POLLIN` 再 `read`；`read` 返回 `0` 必须让上层知道，否则 `poll` 会一直报就绪导致忙等。

**验收**

- [ ] 主循环改成 `while (g_running)` + `read_char(100)`，屏幕上什么都不画也应正常
- [ ] `top` 里 CPU 占用接近 0（不是死循环）
- [ ] `q` 退出、`Ctrl+C` 优雅退出
- [ ] `./build/snake_client < /dev/null` 立刻退出（EOF 路径）
- [ ] `./build/snake_client > /tmp/log.txt` 仍能按 `q` 退出

**常见坑**：把超时当错误退出；把 `EINTR` 当退出；忘记 `revents`；超时单位写成秒；EOF 后死循环。

## 模块 2（2.2）帧缓冲：拼好一帧一次写出

**产出**：`begin_frame() / move_to() / put() / present()` 四件套；画面稳定不闪。
https://emm-gerrit.insta360.cn/c/embedded/camera/AIPL/aipl/+/140386
**学习内容**

- 闪烁的成因：一帧由多次 `write` 组成 + 每帧 `\033[2J` 清屏，终端在「清掉旧画面」和「画完新画面」之间被你看到了
- ANSI：`\033[H` 光标归位（覆盖式重画）与 `\033[2J` 清屏的区别
- `std::string` 的追加与 `reserve`；为什么要避免每帧重新分配
- 回顾 4.3 的 `write_all`：既然它会处理短写，`present()` 里直接复用它

**提示（少量）**

1. 在 `Terminal` 里加一个 `std::string frame_` 成员，构造函数里 `reserve(4096)`。
2. `move_to` 和 `put` 改成往 `frame_` 追加内容（`move_to` 追加的是 `\033[行;列H` 定位序列，行列为 1 基）。
3. 每帧开头用 `\033[H` 或一次 `\033[2J\033[H`（只在必要时清），**不要每帧清屏**。
4. `present()` 就是一次 `write_all(frame_)`；`clear()` 保留立即写的能力，别和帧缓冲混用。

**验收**

- [ ] 边框 + `@` 连续重绘不闪
- [ ] 用 `strace -c -e trace=write ./build/snake_client` 对比：每帧的 `write` 次数应降到个位数（M1 是一帧几百次）
- [ ] 退出后 `stty -a` 中 `icanon`、`echo` 正常

**常见坑**：`frame_` 忘了每帧清空（残影/内存涨）；一半走缓冲一半直接写（顺序错乱）；把 `\033[2J` 存进每帧内容；`present()` 后忘了清空。

## 模块 3（2.3）按键解码：WASD 与方向键

**产出**：`Key` 枚举 + `decode_key()`；角落里显示最近按下的键名用于自测。

**学习内容**

- 终端里方向键的字节序列：`0x1B '[' 'A'/'B'/'C'/'D'`；用真终端的 `showkey -a` 或 `cat -v` 亲眼看一遍
- 「单独按 ESC」与「序列开头」的歧义，以及用**短超时**消歧的思路
- `enum class Key` + 映射表；复习 M1 的 `enum class` 与 `switch` 用法

**提示（少量）**

1. 顺手的顺序：先识别单字节（`w/a/s/d`、`q`），遇到 `0x1B` 再尝试读后续字节。
2. 后续两个字节用 `read_char(10~30)` 的短超时读；凑不齐 `'[' + 字母` 就当作单独的 `Esc`，返回「未知键」即可。
3. 先保持纯粹：`decode_key` 只做「字节 → Key」的翻译，不碰游戏状态；180° 掉头等规则留给 M4 的 `Snake`。
4. 自测方法：不用等画面，直接在角落 `put` 出键名，按一遍全部键核对。

**验收**

- [ ] 方向键四个方向 + WASD 四个方向都能识别，`q` 仍能退出
- [ ] 单按 ESC 不会卡住（立即返回未知键）
- [ ] `printf '\033[A' | ./build/snake_client` 能识别为上（管道测试，不看画面也能验证解码）

**常见坑**：无限等第三个字节导致 ESC 卡死；在 `decode_key` 里直接改游戏状态；把方向键当成三个独立按键处理；用 `getchar` 与 `read` 混用造成缓冲打架。

## 模块 4（2.4）节拍主循环与 `@` 移动

**产出**：固定节拍的重绘循环，`@` 可移动、边界裁剪正确。

**学习内容**

- 用 `poll` 超时充当帧节拍：`read_char(80)` 超时一次 = 一帧；不要额外 `sleep`
- 单向数据流：**输入 → 状态 → 渲染**，渲染函数只读状态
- 边界裁剪；为 M4 预留「输入只是修改方向意图」的意识

**提示（少量）**

1. 循环骨架：`begin_frame()` → 画边框 → 画 `@` → `present()` → `read_char(80)` → 处理按键。
2. `@` 的位置用一个 `row/col` 变量维护，收到方向键就改；越界时**停住**而不是画到边框外。
3. M2 的移动就是「按一次挪一格」，不做自动前进、不做方向队列——M4 那套 `next_dir` 先不引入。
4. 输入处理放在渲染之后，允许一帧延迟，逻辑最简单；别提前优化。

**验收**

- [ ] `@` 能连续移动、可转向，长按不卡顿、不掉帧
- [ ] 撞到边框停住，画面不花
- [ ] 全程 0 warning；`q` 与 `Ctrl+C` 退出后终端正常
- [ ] `git commit -m "feat: M2 poll 输入、帧缓冲与方向键"`

**常见坑**：`poll` 超时之外又加 `sleep`（帧率减半）；忘了 `present()`（整屏不动）；渲染函数里改状态；越界判断写成 `<=` 差一格。

## 六、速查表

**poll 三态**

| 返回值 | 含义 | 处理 |
|---|---|---|
| `> 0` | 有 fd 就绪 | 判 `revents & POLLIN` 后 `read` |
| `0` | 超时 | 当作「这一帧没有输入」 |
| `-1` | 出错 | `EINTR` → 无输入；其余可记录后继续 |

**ANSI 速查**

| 序列 | 含义 | M2 用法 |
|---|---|---|
| `\033[H` | 光标回左上角 | 每帧开头 |
| `\033[2J` | 清屏 | 只在初始化时 |
| `\033[<行>;<列>H` | 定位（1 基） | `move_to` 写入帧缓冲 |
| `\033[?25l/h` | 隐藏/显示光标 | M1 已有，不动 |

**命令备忘**

```bash
man 2 poll                # 本节最该读的手册
showkey -a                # 真终端里看方向键字节序列
strace -c -e trace=write ./build/snake_client   # 看 write 次数
printf '\033[A' | ./build/snake_client          # 管道喂方向键
reset / stty sane         # 花屏救援
```
